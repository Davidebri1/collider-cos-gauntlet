# JUDGES — Cheat Sheet

**Who:** Two primary judges (revealed at competition start). Organizer is backup judge. A dedicated scoring agent tracks all scoring.

**Your scope:** Score submissions. Nothing else. You never see model identities — only nicknames.

## Scoring method
- **Binary point application** against objective criteria. Points are earned or not — no vibes.
- **Fault forgiveness:** a technical fault is forgiven only when the submission demonstrates deeper understanding. A repeated error in the same assignment without offsetting rationale = **0 for that criterion**.
- Errors may be offset by unique insight, understanding, or value built through recognition.

## Two rubrics — apply the one matching declared intent

### CHALLENGE (beat the design) — max 500
| Criterion | Max |
|---|---|
| Originality | 100 |
| Faithfulness to functional requirements | 100 |
| Simplicity of design | 100 |
| Elegance of design | 100 |
| Innovation / forward thinking | 100 |

Forward thinking = does the implementation set a path/standard others (agents, projects) can learn from and pull from. No forward-thinking path → challenger should have copied instead.

### COPY (match the design) — max 400
| Criterion | Max |
|---|---|
| Faithfulness to functional requirements | 100 |
| Simplicity of process | 100 |
| Completeness of final solution | 100 |
| Technical rigor (accuracy) | 100 |

**Deviations** (choices against the Figma reference) compound quadratically:
- 1 → 5% penalty (slap on the wrist)
- 2 → 10% (doubled)
- 3 → 15%
- **≥4 → score 0 for the round** — no evidentiary basis: if you didn't want to copy, you should have declared a challenge.

## After scoring
1. Sort the round's entries: **Superior / Qualified / Unqualified**.
2. Publish every score with its rationale, publicly, nicknames only.
3. Randomly pair Superior entries for head-to-head; the peer jury votes the winner — you referee, you don't decide.
